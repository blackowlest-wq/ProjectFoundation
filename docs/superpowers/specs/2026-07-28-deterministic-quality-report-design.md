# 品質確認画面の機械検証化 設計

## 目的

品質確認画面の自動表示から、AIまたは意味解釈に依存する「不足」「要補足」の判定を外す。JSONの構造、ID参照、実行結果、品質基準など、再実行しても同じ結果になる事実だけをPowerShellで検証し、HTMLはその結果を表示する。

## 対象

- 対象機能: `F-001_ログイン`
- 対象生成スクリプト: `F-001_ログイン_生成.ps1`
- 対象データ: `F-001_ログイン_表示データ.json`
- 対象表示: `F-001_ログイン_コード品質確認.html`

既存の `reviewStatus`、`caseDesignStatus`、指摘の `要補足` は元データに残す。ただし、自動検出結果、確認項目、受入条件の実行判定には使用しない。

## 機械検証する事実

- JSON必須項目の存在、空欄、許可された列挙値
- コレクション間のID重複、未登録参照、双方向参照
- 受入条件・テストケース・実テスト・証跡の紐付け
- テストケースと実テストの実行状態の整合性
- 品質ゲートの状態と対象ケースの実行状態
- カバレッジ基準値と未通過分岐
- 明示された未実行、失敗、保留、未通過

## 自動検出しない情報

以下は入力されたレビュー記録として保持するが、機械検証結果には含めない。

- 期待結果の意味的な妥当性
- テスト観点の十分性
- `reviewStatus`、`caseDesignStatus` に基づく不足判定
- `findings.status` が `要補足` であることによる確認項目生成

## 表示方針

「不足・保留」パネルは機械検証結果を示す名称へ変更する。各項目には、機械的に確認したカテゴリ、対象ID、元データ上の根拠を表示する。レビュー状態や `要補足` は、必要な場合に指摘一覧または入力記録として表示するが、合否・品質評価として表示しない。

## テスト方針

- 現行の正常データで生成・検証が成功すること
- `reviewStatus`、`caseDesignStatus`、`要補足` が存在しても、機械検証結果へ追加されないこと
- 一時コピーしたJSONから必須項目、参照ID、紐付け、実行結果、基準値を変更し、検証が決定的に失敗すること
- HTMLが機械検証結果、未実行、未通過、保留を表示し、レビュー状態だけでは確認項目を増やさないこと

## 変更しないこと

- アプリ本体の認証処理、テスト、DB、Oracle実行環境
- 既存のレビュー記録そのもの
- 既存の未コミット変更の破棄、リセット、上書き
