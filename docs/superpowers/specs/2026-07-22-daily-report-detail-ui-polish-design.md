# 日報詳細画面の表示調整 設計

## 目的

上長向けの日報詳細画面について、利用者が確認した表示上の違和感を解消する。

## 対象

- 日報詳細見出し下に表示される日報IDを非表示にする。
- 承認操作と一覧遷移ボタンの間隔・上下余白を広げる。
- `承認待ち` などのステータスピルを、左端だけでなく全体が同じ状態色になるように表示する。

## 対象外

- 承認・差戻しAPI、状態遷移、認可、エラー処理の変更。
- 日報詳細の項目、作業明細、ボタン文言の変更。
- カレンダーセルの状態色そのものの変更。

## 実装方針

`frontend/src/dailyReport/DailyReportDetail.tsx` と `frontend/src/styles.css` の範囲に限定する。

- 日報IDの表示要素を削除し、DOMにも残さない。
- 詳細画面の操作領域に専用クラスを付け、既存の共通 `.actions` の挙動を壊さずに、操作行間の余白とボタン間隔を設定する。
- カレンダーセル向けの `border-left-color` 指定と、詳細画面のステータスピル向けの全周ボーダー指定を分離する。

## 受入条件

- AC-DUI-001: 日報詳細画面に日報ID文字列が表示されない。
- AC-DUI-002: 承認操作ボタンと一覧遷移ボタンが詰まらず、操作領域に視認できる間隔がある。
- AC-DUI-003: `PENDING` のステータスピルは背景色と外枠色が全体に適用され、左端だけが強調された表示にならない。
- AC-DUI-004: 承認・差戻し・一覧遷移の既存操作とAPI呼び出しは変更されない。

## テスト方針

- `frontend/test/DailyReportApprovalPanel.test.tsx` に、日報ID非表示と操作要素の維持を確認するUIテストを追加する。
- 既存の承認・差戻し・フォーカス制御テストを回帰実行する。
- `npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run build` を実行する。
- ステータスピルの色は、実装クラスを確認するテストとブラウザでの目視確認を組み合わせる。

## 設計自己レビュー

- 仕様外のAPI・DB・認証変更を含めていない。
- 日報IDはCSS隠しではなくDOMから削除するため、利用者要望の「非表示」と一致する。
- ステータス色の変更対象を詳細画面のピルに限定し、カレンダーセルの左ボーダー表現を維持する。
- 操作の実装契約とAPI呼び出しは変更せず、既存回帰テストで保護する。
