# 品質確認表示データのテンプレート化 設計仕様

## 目的

コード品質確認画面を機能単位で追加するときの入力形式を固定し、JSONの必須項目、ID、紐付け、実行結果、品質ゲートを機械的に検証できるようにする。F-001固有のIDをテストコードへ埋め込まず、他機能へ展開できる形式にする。

## 対象

- `docs/AI活用開発研究/コード品質確認画面`配下の機能別表示データ
- 機能別生成スクリプトと一括実行スクリプト
- 機能別表示方針テストの共通契約部分

## 対象外

- アプリ本体の認証処理、DB、Oracle、Frontend、Backendの実装
- Markdownの自由記述からのAIまたは正規表現による自動生成
- `reviewStatus`、`caseDesignStatus`、`要補足`の意味評価自動化
- F-001の既存JSONを別ファイルへ分割する移行

## 採用方式

### テンプレート

共通テンプレートを`docs/AI活用開発研究/コード品質確認画面`配下へ配置する。テンプレートは、機能別フォルダへコピーして機能固有の値を入力するための有効なJSONとする。

固定するトップレベル項目は次のとおりとする。

```text
schemaVersion
feature
acceptanceCriteria
qualityGates
rootCauses
testCases
viewpoints
testImplementations
evidence
findings
coverage
sources
```

テンプレートには生成物である`automatedFindings`を含めない。これは生成スクリプトが、入力データから毎回決定的に生成する。

### データとレビュー記録の境界

- 必須項目、ID、参照ID、実行状態、ゲート、カバレッジ、証跡パスは機械検証対象とする。
- `reviewStatus`、`caseDesignStatus`、`findings.status=要補足`は入力されたレビュー記録として保持する。
- レビュー記録の意味を解釈して自動的に「不足」「合格」「評価A」などを生成しない。

### 汎用契約テスト

F-001固有のIDを直接参照するテストを共通契約から除外する。共通テストは次を検証する。

- テンプレートまたは機能別JSONの必須トップレベル項目
- 各コレクションの必須項目
- 全コレクションのID一意性
- 受入条件、ケース、実テスト、証跡、指摘、観点、ソースの参照整合性
- 受入条件とテストケースの双方向紐付け
- `automatedFindings`に意味評価カテゴリが入らないこと
- 実行失敗、未実行、ゲート未通過、カバレッジ未通過、明示的保留の機械検証

機能固有の回帰確認が必要な場合は、共通契約テストとは別の機能別テストへ記載する。

## データフロー

```text
品質確認表示データ.template.json
        ↓ コピー・機能固有値入力
機能別表示データ.json
        ↓ 生成スクリプト -ValidateOnly
必須項目・参照・ファイル・実行状態・ゲート・カバレッジ検証
        ↓ 生成スクリプト
自己完結HTML + automatedFindings
        ↓ 一括実行 / Docs Simpleゲート
テスト・検証・生成結果を確認
```

## エラー方針

- 必須項目、未登録ID、重複ID、参照不一致、証跡ファイル不存在は非0終了とする。
- 入力に意味評価が記録されていても、機械検証結果へ自動追加しない。
- `automatedFindings`が欠落した場合は生成後の表示方針テストで検出する。
- 実行未確認やOracle資格情報エラーは「未実行」「保留」として事実を表示し、合格判定へ変換しない。

## ファイル配置

```text
docs/AI活用開発研究/コード品質確認画面/
├─ 品質確認表示データ.template.json
└─ F-xxx_機能名/
   ├─ F-xxx_機能名_表示データ.json
   ├─ F-xxx_機能名_生成.ps1
   ├─ F-xxx_機能名_表示方針.tests.ps1
   ├─ F-xxx_機能名_コード品質確認.html
   └─ README.md
```

既存のF-001フォルダは参照例として維持し、テンプレート導入時に既存データを機械的に上書きしない。

## 完了条件

- テンプレートがJSONとして読み込める。
- テンプレートの必須構造とステータス規約を検証できる。
- F-001の表示方針テストがF-001固有の共通契約判定なしで成功する。
- F-001の一括実行、`ValidateOnly`、HTML生成、Docs Simpleゲートが成功する。
- 既存のレビュー記録、機械検証結果、HTML表示に意図しない変更がない。
- テンプレート利用手順と未実行項目をREADME・作業記録へ残す。

## 残るリスク

- 機能固有の期待結果や特殊な状態遷移は、テンプレートだけでは表現できない場合がある。
- 既存のF-001表示方針テストを完全な共通テストへ分割する際、機能固有の回帰確認を誤って削除しない必要がある。
- 実ブラウザ表示、Oracle実機、Frontend/BackendのFull実行は、このテンプレート化だけでは代替しない。
