# 日報監査日時フォーマット設計

## 目的

日報画面で表示する提出日時・承認日時・差戻し日時からISO 8601の区切り文字とタイムゾーン表記を取り除き、利用者向けの `YYYY-MM-DD HH:mm:ss` 形式で表示する。

## 方針

- API DTOの`OffsetDateTime`契約は変更しない。
- `frontend/src/dailyReport`内に表示専用の共通フォーマッタを追加する。
- 有効なISO日時は、元の文字列に含まれる日付・時刻を使って`YYYY-MM-DD HH:mm:ss`へ変換する。
- ミリ秒が含まれる場合は秒までを表示し、ミリ秒は表示しない。
- ブラウザのローカルタイムゾーンへの変換は行わない。
- `null`または空文字は`-`として表示する。
- 対象画面は日報詳細、日報カレンダー一覧、未承認一覧、日報編集画面とする。

## 代替案と採用理由

1. 各画面で個別に文字列置換する案は、同じ日時仕様が重複し、画面間で表示差異が生じやすいため採用しない。
2. Backend DTOを表示用文字列へ変更する案は、APIの日時型契約とタイムゾーン情報を失うため採用しない。
3. 日報機能内の共通フォーマッタを使う案を採用する。表示責務をFrontendへ限定し、4画面の表示を一貫させられるためである。

## テスト方針

- 共通フォーマッタの正常値、ミリ秒付き値、`null`、空文字、形式不正値をUnitテストで確認する。
- 日報編集画面の差戻し日時、日報詳細の提出・承認・差戻し日時、一覧画面の提出・承認日時が表示形式を使うことを画面テストで確認する。
- 既存のnull時`-`表示、日報機能の対象Unit、typecheck、lint、buildを回帰確認する。
