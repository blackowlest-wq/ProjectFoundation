## 品質ゲート案

- すべての通常テストが成功している。
- TypeScript型チェックが成功している。
- フロントビルドが成功している。
- E2Eが成功している。
- 実Backend/Oracle E2Eが対象workflowで成功し、Backendログ・Playwrightレポート・失敗時traceを確認できる。
- Frontend / Backendのcoverage report fileが生成され、HTMLと集計ファイルの存在を確認できる。
- Statements / Branches / Functions / Lines、およびINSTRUCTION / BRANCH / METHOD / LINEの4指標がそれぞれ85%以上である。
- Branches / BRANCHの未充足箇所をレビューし、追加テストまたは保留理由を記録している。
- CIで保持されたcoverage artifactを確認し、失敗時も追跡に必要なreportを回収できる。
- 静的解析を導入済みの場合、重大以上の指摘が残っていない。
- Oracle未実行やreport未生成がある場合は、理由と再確認条件を作業記録に残す。
- バックエンドテストが `backend/config/oracle-test.properties` を読み込む共通のOracle入口を通じて実行されたことを確認する。具体的な実行方法は [品質ゲート運用.md](品質ゲート運用.md) と `scripts/check.ps1` を参照する。

### 実装後の判定・保留

- FullはFrontend lint/typecheck/unit 190件/build、Backend Spotless/Checkstyle/SpotBugs/PMD、全contract、project-lint、endpoint contract、connectionsを含めて成功。FrontendCoverageは190/190、Statements 96.08%、Branches 92.38%、Functions 97.77%、Lines 95.94%。Chromium E2Eは21/21 PASS。
- TC-PFL-074は固定HEAD `905a9676a7d48a86bf9aab6fb34dcbf08c65f402`との5 blob照合後も、Stage 1直後・Stage 2前の公開A/D不変artifactが未取得のため`evidenceStatus=notCaptured`、`decision=hold`。これは歴史baseline固有のHOLDで、sourceArtifact pin lifecycleとは別契約であり、post-fix TC-PFL-078〜082とも分離する。
- BackendCoverage/Oracle/E2EOracleは、固定SQL cleanupが設定済みDBを書き換えるため対象DB明示承認なしでは実行しない。以前のfull backend testはORA-01017で93 errors。専用test DB/runner/identity/cleanup承認が揃ったmain pushまたは手動実行を再確認条件とする。
