# 統合品質記録様式

## 目的

機能単位の受入条件、テスト、レビュー、品質ゲート、保留事項を一つの正本へ集約する。専門レビュー資料と作業記録を削除するためではなく、同じ結果を複数資料へ転記する作業を減らすために使用する。

## 使い方

- 機能追加または大きめの修正ごとに一つ作成する。
- AC、TC、RT、FINDは別名前空間のIDを使用する。
- 専門レビュー資料には根拠と指摘を残し、実行結果・CI URL・未実行理由はこの記録から参照する。
- 未実行、失敗、保留を成功扱いにしない。
- 接続URL、ユーザー名、パスワード、Cookie、トークンを記録しない。

## 記録様式

```text
# [機能名] 統合品質記録

対象:
対象外:
既存変更:

| AC ID | TC ID | RT ID/確認方法 | 期待結果 | レビュー結果 | FIND ID | 保留・再確認条件 |

## 7. 指摘の標準化判定

| FIND ID | 判定 | 反映先 | 理由 | 次回から守ること |
| --- | --- | --- | --- | --- |
| FIND-xxx | 個別対応 / 既存観点で対応 / 標準化候補 / 対象外 / 保留 |  |  |  |

## 8. 証跡リンク

- 設計書:

- テストケースレビュー:
- 専門レビュー:
- 作業記録:
- 指摘一覧:
```

## 正本の境界

| 資料 | 正本とする内容 | この様式へ重複転記しない内容 |
| --- | --- | --- |
| 設計書 | 仕様、設計、対象範囲 | 実行結果、CI URL |
| 正本テストケース | ケース、期待結果、テスト層 | 同じケースのレビュー結論全文 |
| 専門レビュー | 観点別の根拠、指摘、判定 | 同じゲート表の全文 |
| 作業記録 | 作業のWhat、判断、未実行理由 | 専門レビュー本文の再掲 |
| 指摘一覧 | 問題、対応、標準化判定 | コマンドログ全文 |
| 統合品質記録 | ACからゲートまでの統合判定、証跡リンク | 各資料の詳細本文 |
