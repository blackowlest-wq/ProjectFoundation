# ADRテンプレート

## 目的

将来の保守担当者が、重要な設計判断の背景、採用理由、却下した代替案、前提・制約、関連資料を追跡できるようにする。

ADRは、長期にわたって有効な設計判断の正本とする。作業記録は作業の経過、統合品質記録はテスト・レビュー・品質ゲートの結果を担い、ADRの内容を重複転記しない。

## 適用する判断

次のいずれかに該当する重要な判断だけをADRへ記録する。

- 複数機能へ影響する構造や共通部品
- API、DB、外部システムとの契約
- 認証認可、セキュリティ、ログ、復旧に関わる制約
- 将来の変更方法を強く制約する方式
- 複数の代替案から選択した重要な判断

局所的で影響範囲が小さい判断や、コードから明確に読み取れる実装上の選択には、ADRを必須にしない。必要に応じてコードコメントまたは作業記録へ残す。

## 記録ルール

- 1つのADRにつき、原則として1つの設計判断を記録する。
- 判断を変更する場合は、Accepted済みのADRを直接書き換えず、新しいADRを作成して置換元を示す。
- AIとの対話全文や、AIが生成したコードの行単位の採用範囲は保存しない。
- テスト、レビュー、コード差分、ログなどの実行可能な証拠は、統合品質記録や作業記録で管理し、ADRへ重複転記しない。

## 記録様式

```text
ID:
タイトル:
日付:
状態: Proposed / Accepted / Superseded / Rejected

背景・問題:

決定:

検討した代替案と不採用理由:

前提・制約:

関連資料:
```

## 状態の扱い

| 状態 | 意味 |
| --- | --- |
| Proposed | 検討中で、まだ正式採用していない |
| Accepted | 現在の設計として採用している |
| Superseded | 新しいADRに置き換えられた |
| Rejected | 検討したが採用しなかった |
