# ADR-DRE-003 日報登録更新の履歴保持と明細更新方式

ID: ADR-DRE-003
タイトル: 日報登録更新の履歴保持と明細更新方式
日付: 2026-08-04
状態: Accepted

## 背景・問題

日報は数年単位で参照され、利用者マスタや作業マスタが後から変更される。登録時点の業務判断と、編集時の明細全体の整合性を保つ必要がある。

## 決定

- 日報登録時に、認証主体の社員番号、氏名、所属を日報へスナップショット保存する。
- 勤務時間の計算結果と社員の勤務設定を、登録時の入力検証・計算結果として日報へ保存する。
- 作業明細は差分APIではなく、入力配列を保存時に全差し替えする。
- 更新時も、認証主体、休日区分、勤務時刻、マスタID、作業明細、合計時間を一括検証してから保存する。

## 検討した代替案と不採用理由

- 表示時に利用者マスタを参照する案: 所属・氏名の変更で過去日報の意味が変わるため不採用。
- 作業明細を差分APIで個別更新する案: 画面の削除状態とBackendの明細状態がずれる経路が増えるため不採用。
- 入力値を保存して表示時に毎回再計算する案: マスタ変更で過去の計算結果が変わるため不採用。

## 前提・制約

- Backendが保存前の最終入力検証と勤務時間計算を行う。
- 保存済み作業明細の表示名は、マスタが無効化された場合でもIDへフォールバックして履歴を表示できる。
- 既存の認証・認可・CSRF・状態遷移契約を維持する。
- マスタ変更後に現在のルールとの不整合が見つかる場合があるため、保存済み日報の再検証ルールを維持する。
- 明細全差し替えは更新時に全明細を送る必要があるため、画面とAPIの入力配列契約を変更時に同時確認する。
