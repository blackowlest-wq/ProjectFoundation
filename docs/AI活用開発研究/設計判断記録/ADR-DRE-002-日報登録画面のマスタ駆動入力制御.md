# ADR-DRE-002 日報登録画面のマスタ駆動入力制御

ID: ADR-DRE-002
タイトル: 日報登録画面のマスタ駆動入力制御
日付: 2026-08-04
状態: Accepted

## 背景・問題

休日区分ごとの勤務時刻・作業明細の入力可否は、DBマスタの`requiresWorkTime`と`allowsWorkItems`で管理されている。画面側が休日区分コードを固定判定したり、マスタ未取得時に固定IDを生成したりすると、Backendと画面の制御が乖離する。

## 決定

- 画面の入力可否、区分変更時の入力クリア、保存前の入力検証は、取得した休日区分マスタ属性を正とする。
- 案件・作業分類のマスタ取得前または空集合時は、作業明細追加を無効にする。
- 作業明細の初期値・追加値には固定の案件ID・作業分類IDを使わず、取得済みマスタの値だけを使う。
- マスタにない休日区分コードも、マスタ属性が返る限り画面で扱える型にする。

## 検討した代替案と不採用理由

- `PAID_LEAVE`や`HOLIDAY`を画面で固定判定する案: 区分追加・属性変更時にBackendと乖離するため不採用。
- マスタ未取得時に`P001`／`WC001`を使う案: 利用者に見えない無効な入力を作るため不採用。
- マスタ未取得時も追加操作を許す案: 保存できない入力を先に作るため不採用。

## 前提・制約

- Backendは保存時に休日区分、案件、作業分類を再検証する。
- 画面はマスタ取得失敗を保存可能な状態として扱わない。
- 現在の初期データは`DataInitializer`とマスタAPIの契約で提供される。
- マスタ取得に失敗した場合、利用者は取得復旧まで作業明細を追加できない。
- マスタ属性の変更は画面操作の可否も変えるため、マスタ変更時には画面Unit/E2EとBackend業務ルールを同時に確認する。
