# ADR-DRE-001 日報登録画面の計算表示契約

ID: ADR-DRE-001
タイトル: 日報登録画面の計算表示契約
日付: 2026-08-04
状態: Accepted

## 背景・問題

日報の休憩時間、実勤務時間、通常勤務時間、残業時間、深夜時間はBackendの勤務ルールで計算する。一方、登録画面は保存前の入力値から計算結果を推測表示せず、保存後にBackendが確定した値を利用者と保守担当者が確認できる必要がある。

## 決定

- 勤務時間の計算結果はBackendの`TimeRules`を正とする。
- 登録・更新APIの概要レスポンス契約は維持する。
- 保存後、登録画面は詳細APIを再取得し、Backendが確定した計算結果を時分形式で表示する。
- 入力を変更した場合は、変更前の計算結果を表示し続けず、保存後に再取得する状態へ戻す。
- 詳細再取得に失敗した場合は、保存失敗とは区別したメッセージを表示する。

## 検討した代替案と不採用理由

- Frontendで勤務時間を再計算する案: Backendと計算基準が二重化し、マスタ変更時に結果が乖離するため不採用。
- 登録・更新APIのレスポンスを詳細DTOへ変更する案: 既存の概要レスポンス契約を変更し、登録処理と表示DTOを強く結合するため不採用。
- 計算結果を表示しない案: S-003/F-002が求める確認可能性を満たさないため不採用。

## 前提・制約

- 休憩区分、勤務区分、休日区分はBackendが有効なマスタから取得する。
- 未保存の入力に対する計算結果を画面上で確定値として扱わない。
- 保存後の詳細再取得が追加通信となる。
- 保存後に詳細APIを取得するため、通信失敗時は保存済みでも表示更新が遅延する。この場合は保存失敗と誤認させない。
- 計算ロジックを変更する場合は、登録API、詳細API、登録画面の表示テストを同時に確認する。
