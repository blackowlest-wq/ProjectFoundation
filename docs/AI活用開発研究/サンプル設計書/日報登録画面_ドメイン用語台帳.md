# サンプルアプリ 日報登録画面 ドメイン用語台帳

更新日: 2026-08-05

## 目的

日報登録画面（S-003、F-002）で使用する業務用語、状態名、API・コード上の識別子を対応付ける。

本資料は、担当者変更時の業務知識の引継ぎ、設計書・コード・テストの命名統一、RAGの検索対象の正規化に使用する。既存の業務ルール、受入条件、状態遷移、ADR、テストケースを置き換えず、それらを同じ用語で参照するための台帳とする。

## 対象範囲

- 主対象: F-002 日報登録、S-003 日報登録画面
- 状態名称: 日報登録画面の表示・操作制御に必要な範囲
- 関連する参照: F-003 日報編集、F-006 日報提出、F-009 日報再提出
- 対象外: 承認・差戻しの詳細業務設計、月次集計、CSV出力の個別用語

F-003、F-006、F-009の詳細ルールは、既存の「入力チェック・業務ルール一覧」と「状態遷移・業務フロー設計」を正本とする。

## 用語の運用ルール

1. 新しい設計書、コード、テストでは、表の「正式な日本語」と「コード上の正規識別子」を優先して使用する。
2. 別名・旧称は検索用に保持するが、新規の変数名、関数名、ファイル名には使用しない。
3. 同じ単語でも業務境界によって意味が異なる場合は、用語を無理に統合せず、「業務境界」列で区別する。
4. 業務ルールの追加・変更では、新しいID体系を作らず、既存の`V-*`、`AC-*`、`TC-*`、`RT-*`、`FIND-*`、`ADR-*`を利用する。
5. 用語の意味を変更する場合は、旧称を削除せず、変更日、変更理由、関連資料を記録する。
6. 仕様で意味を確定できない用語は推測で正式化せず、「確認事項」または「保留」として扱う。

## 業務境界

| 業務境界 | この画面で扱う意味 | 代表的な用語 |
| --- | --- | --- |
| 日報管理 | 社員が日付単位の日報と作業明細を登録し、業務ルールに従って保存する | 日報、日報明細、休日区分、実勤務時間 |
| 認証・認可 | 現在ログインしている利用者と、その利用者が操作できる日報の範囲を判定する | 利用者、社員本人、ロール、権限 |
| マスタ管理 | 休日区分、休憩区分、勤務区分、案件、作業分類の選択肢と属性を提供する | マスタ、休日区分、休憩区分、勤務区分 |

「社員」は日報管理上の日報所有者を表し、「利用者」は認証されたアカウントを表す。認証の`userId`と日報の`employeeId`を同じ意味として扱わない。

## 日報登録画面の用語

| 正式な日本語 | コード上の正規識別子 | 意味 | 別名・注意点 | 関連資料 |
| --- | --- | --- | --- | --- |
| 日報 | `DailyReportEntity`、`DailyReportRequest`、`DailyReportResponse` | 社員が一日単位で登録する勤務・作業の記録 | `DailyReportEntity`は永続化、`DailyReportRequest`/`Response`はAPI契約を表す。DB行だけではなく、日付、休日区分、勤務時間、作業明細、状態を含む業務上の記録 | F-002-AC-001、A-008 |
| 日報明細 | `DailyReportWorkItemEntity`、`DailyReportRequest.WorkItemRequest`、`workItems` | 日報に含まれる案件ごとの作業記録 | `DailyReportWorkItemEntity`は永続化、`WorkItemRequest`はAPI入力を表す。「作業明細」と同義で、日報とは別の独立した提出単位ではない | V-ITEM-* |
| 日付 | `reportDate` | 日報の対象となる業務日 | 登録日時や提出日時とは異なる | V-REP-001、F-002-AC-011 |
| 社員 | `employeeId`、`employeeName` | 日報を所有し登録する業務上の社員 | 認証アカウントの`userId`や一般的な「利用者」と混同しない | V-AUTH-001、F-002-AC-017 |
| 社員名 | `employeeName` | 日報登録画面に表示する日報所有者の氏名 | 画面ラベルは「社員名」。認証境界の「利用者名」とは区別する | S-003、F-002-AC-017 |
| 登録 | `createDailyReport`、`POST /api/daily-reports` | 新しい日報を作成して保存する操作 | 新規日報の保存結果は`DRAFT`。画面操作では「保存」と表示される場合がある | A-008、F-002-AC-018 |
| 保存 | `saveDraft`、`save`、`PUT /api/daily-reports/{reportId}` | 日報の入力内容を永続化する操作 | 保存だけでは提出状態へ進まない。新規登録では登録API、既存日報では編集APIを使う | A-008、A-010、F-003-AC-007 |
| 提出 | `submit` | 入力済みの日報を承認待ちへ進める操作 | 「保存」「登録」「申請」と同義ではない。状態を`DRAFT`から`PENDING`へ変更する | V-STAT-003、V-TRN-001～002、F-006-AC-001～003 |
| 休日区分 | `holidayType`、`HolidayType` | 勤務日、休日、有給休暇、半日休などの日単位の区分 | 固定コードだけで判定せず、マスタ属性`requiresWorkTime`と`allowsWorkItems`を利用する | V-REP-003～004、ADR-DRE-002 |
| 通常勤務 | `WORKDAY` | 通常の勤務時間と作業明細を登録する休日区分 | 画面表示名はマスタから取得する | V-REP-005～012 |
| 休日 | `HOLIDAY` | 勤務を行わない休日、または休日出勤を行う区分 | 作業なしと作業ありの両方があり得る | V-ITEM-001、V-ITEM-008 |
| 有給休暇 | `PAID_LEAVE` | 勤務時刻、休憩、作業明細を登録しない区分 | 勤務時間や作業明細の入力を許可しない | V-ITEM-007、V-REP-005～006 |
| 午前休 | `AM_OFF` | 午前休を取得し、午後の勤務を登録する区分 | 実際の入力可否はマスタ属性と業務ルールで決まる | 休日区分別業務ルール |
| 午後休 | `PM_OFF` | 午後休を取得し、午前の勤務を登録する区分 | 実際の入力可否はマスタ属性と業務ルールで決まる | 休日区分別業務ルール |
| 勤務開始時刻 | `startTime` | 日報上の勤務開始時刻 | 登録画面の入力値。分単位のDB値や表示用文字列とは区別する | V-REP-005、V-REP-008 |
| 勤務終了時刻 | `endTime` | 日報上の勤務終了時刻 | 勤務開始時刻以前は登録不可 | V-REP-006、V-REP-008 |
| 休憩区分 | `breakTypeId`、`breakTypeName` | 社員に設定された休憩ルールの区分 | 登録画面で自由入力する値ではなく、社員に紐づくマスタ情報を表示する | V-REP-007、ADR-DRE-002 |
| 自動算出休憩時間 | `breakMinutes` | 休憩区分と勤務時刻から算出される休憩時間 | 日報登録APIの入力値として自由に受け取らない | F-002-AC-002、V-REP-009 |
| 勤務区分 | `workTimeTypeId`、`workTimeTypeName` | 社員に設定された通常勤務・残業・深夜の計算ルール | 登録画面で自由入力する値ではなく、社員に紐づくマスタ情報を表示する | F-002-AC-003、ADR-DRE-002 |
| 実勤務時間 | 内部: `actualWorkMinutes`、API: `workMinutes`（日報） | 勤務時間から休憩時間を差し引いた、実際に勤務した時間 | API項目名は互換性のため維持し、内部コードでは実勤務時間であることを明示する | V-REP-010、V-ITEM-006 |
| 通常勤務時間 | `regularWorkMinutes` | 勤務区分に基づく通常勤務時間 | 実勤務時間の内訳の一つ | V-REP-012 |
| 残業時間 | `overtimeWorkMinutes` | 勤務区分に基づく残業時間 | 実勤務時間の内訳の一つ | V-REP-012 |
| 深夜時間 | `nightWorkMinutes` | 勤務区分に基づく深夜時間 | 実勤務時間の内訳の一つ | V-REP-012 |
| 作業時間 | 内部: `workItemMinutes`、API: `workMinutes`（日報明細） | 一つの日報明細に入力する作業時間 | API項目名は互換性のため維持し、内部コードでは日報明細の時間であることを明示する | V-ITEM-004～006 |
| 作業時間合計 | `totalWorkItemMinutes` | 日報明細の作業時間を合計した値 | 実勤務時間と一致することを確認する | F-002-AC-004、V-ITEM-006 |
| 案件 | `projectId`、`projectName` | 作業の対象となる案件 | 案件マスタの選択肢から指定する | V-ITEM-002 |
| 作業分類 | `workCategoryId`、`workCategoryName` | 作業内容の分類 | 作業分類マスタの選択肢から指定する | V-ITEM-003 |
| 備考 | `remarks` | 日報に付加する自由記載 | 差戻しコメントとは別の項目 | V-REP-013 |

## 状態用語

状態の詳細な遷移、操作主体、条件、副作用は、`状態遷移・業務フロー設計.md`を正本とする。

| 正式な日本語 | API・コード値 | 意味 | 日報登録画面での扱い |
| --- | --- | --- | --- |
| 下書き | `DRAFT`、`approvalStatus` | 日報を保存済みだが、承認処理へ提出していない状態 | 新規登録後の状態。社員が編集・保存・提出できる。旧称は「未提出」 |
| 承認待ち | `PENDING` | 提出済みで、上長の承認または差戻しを待っている状態 | 編集・保存・提出を許可しない |
| 差戻し | `REJECTED` | 上長から差戻しされ、社員の修正を待っている状態 | 詳細な編集・再提出はF-009の範囲。状態の意味は日報登録画面でも表示制御に使用する |
| 承認済み | `APPROVED` | 上長が承認し、集計・CSV出力の対象になる状態 | 編集・保存・提出を許可しない |

「未提出」は旧称として検索用に保持し、新しい設計書、コードコメント、画面、テストの正式な状態名は「下書き」とする。「未承認」は複数状態を含み得るため、個別の状態名としては使用しない。

## 業務ルール・受入条件・テストとの対応

用語台帳は、既存のID体系を再利用して次のように接続する。

| 業務概念 | 業務ルール | 受入条件 | 主なテスト層 |
| --- | --- | --- | --- |
| 日報登録後は下書きになる | V-TRN-001、V-TRN-002、V-REP-* | F-002-AC-018 | Backend Unit/API、Frontend Unit、E2E |
| 休日区分に応じて入力可否が変わる | V-REP-003～012、V-ITEM-* | F-002-AC-001～009、F-002-AC-014～016 | Backend Unit、Frontend Unit、API |
| 実勤務時間と作業時間合計が一致する | V-REP-010～012、V-ITEM-004～006 | F-002-AC-004、F-002-AC-008、F-002-AC-013 | `TimeRules` Unit、Backend API |
| 同一社員・同一日の重複登録を拒否する | V-REP-002 | F-002-AC-010 | Backend API/Oracle |
| 他社員の日報を登録できない | V-AUTH-001～002 | F-002-AC-017 | Backend API/Oracle、E2E |

受入条件、テストケース、実テストの詳細な対応関係は、既存の正本テストケースと統合品質記録で管理する。本資料へ同じ対応表を重複して増やさない。

## 更新時の確認

次の変更を行う場合は、本資料と関連する正本資料の影響を確認する。

| 変更 | 確認対象 |
| --- | --- |
| 用語、表示名、API名、フィールド名を変更する | 本資料、画面設計、API一覧、実装、テスト名、RAG用メタデータ |
| 状態を追加・変更する | 本資料、状態遷移、`V-STAT-*`、`V-TRN-*`、受入条件、状態別テスト |
| 休日区分のコード・属性を変更する | 本資料、マスタAPI、休日区分別業務ルール、画面・Backendの入力制御、関連ADR |
| 実勤務時間・作業時間の計算を変更する | 本資料、業務ルール、計算ロジック、`TimeRules`テスト、関連ADR |
| 新しい別名・旧称が判明する | 本資料へ別名を追加し、新規識別子には正式名称を使用する |

更新時に意味が確定していない場合は、用語を追加せず、確認事項・仮定・保留として作業記録へ残す。

## RAGでの利用

- 本資料は、日報登録画面の業務用語を説明する高信頼の参照資料として扱う。
- 正式な用語と別名を同じ検索対象に含めるが、回答や新規コードでは正式な用語を優先する。
- 検索メタデータには、`feature=F-002`、`screen=S-003`、`context=daily-report`、`documentType=domain-glossary`、更新日、正本資料への参照を付与する。
- 状態や業務ルールを回答する場合は、本資料だけで断定せず、関連する状態遷移、業務ルール、受入条件、ADRを根拠として提示する。
- 旧版を検索対象に残す場合は、現行版と混同しないように`superseded`などの状態を付与する。

## 確認事項・保留事項

- `workMinutes`は日報の実勤務時間と日報明細の作業時間で使用されるため、既存API互換性を維持しつつ、新規コードでは所属オブジェクトを含む名称で誤読を避ける。
- 休日区分の具体的なコードはAPI資料に定義するが、画面の入力可否は固定コードではなく、マスタ属性と業務ルールを正本とする。
- 本資料の用語を他機能へ展開する際は、同じ用語が別の業務境界で同じ意味かを確認してから共通用語へ昇格する。
