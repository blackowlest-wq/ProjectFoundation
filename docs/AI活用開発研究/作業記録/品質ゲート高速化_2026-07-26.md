# 品質ゲート高速化（2026-07-26）

## 開発モード

簡易修正モード。個別のplan/specは作成せず、本記録へ受入条件、検証結果、未実行項目、残るリスクを集約する。

## 目的

Frontendの型チェック重複、Maven起動・コンパイル重複、GitHub Actionsの依存取得とFull実行の重複を減らし、main push後の品質ゲートの待ち時間を短縮する。

## 変更内容

- `frontend/package.json`へ`build:ci`（`vite build`のみ）を追加した。
- `scripts/check.ps1`のFullFrontendとSimple Frontend buildを`build:ci`へ変更した。
- Mavenの`test-compile`、Spotless、Checkstyle、SpotBugsを`backend-quality`の1回のMaven起動へ統合した。
- `FullFrontend`と`FullBackend`のCI taskを追加した。Backend taskには既存の品質ゲート契約テストを含めた。
- Quality workflowをWindows上のFrontend / Backend 2 jobへ分割し、Linux Full jobを削除した。
- Quality / Oracle workflowのNode.jsへnpmキャッシュ、JavaへMavenキャッシュを追加した。
- 既存の品質ゲート契約テストとSimple Mode契約テストへ、新しい実行境界を追加した。
- 品質ゲート運用資料のjob名、実行task、並列実行方針、required status check名を更新した。

## テスト・確認

- Focused Unit: `scripts/coverage-gate.tests.ps1`、`scripts/simple-mode.tests.ps1`、`scripts/pre-push.tests.ps1`。品質ゲート定義とworkflow契約の変更であり、業務機能のFocused Unitは対象外。
- `pwsh -NoProfile -File scripts/coverage-gate.tests.ps1`: 成功。
- `pwsh -NoProfile -File scripts/simple-mode.tests.ps1`: 成功。
- `pwsh -NoProfile -File scripts/pre-push.tests.ps1`: 成功。
- `pwsh -NoProfile -File scripts/check.ps1 -CiTask FullFrontend`: 成功。Frontend lint 13.78秒、typecheck 10.83秒、unit 51.32秒、`build:ci` 11.15秒、132テスト成功。
- `pwsh -NoProfile -File scripts/check.ps1 -CiTask FullBackend`: 成功。統合Maven実行と3件の契約テストが成功し、Maven表示のTotal timeは48.966秒。
- 変更前相当のFrontend `build`（`tsc --noEmit && vite build`）は17.15秒、変更後の`build:ci`（`vite build`のみ）は11.15秒で、ビルド工程は6.00秒（35.0%）短縮した。
- 変更前相当のMaven 4回起動は65.94秒、変更後の統合Maven 1回起動は40.38秒で、Backend品質検査部分は25.56秒（38.8%）短縮した。いずれも同一ローカル環境の連続実行であり、GitHub-hosted runnerの実時間とは異なる。
- `git diff --check`: 成功。
- Markdown lint、pre-commit / pre-push、main push後のE2E、coverage、Oracleは最終差分確定後またはCIへ委譲する。

## 未実行項目・残るリスク

- GitHub-hosted runner上での実workflow実行は未確認。cache hit率と実際のjob並列化時間はmain push後に確認する。
- CIのFull部分は、変更前のWindows/Linux各Fullによる同一検査の2重実行から、Windows Frontend / Backend各1回へ整理したため、検査本体の実行量は概ね半減する。Frontend / Backend並列化によるCI待ち時間の短縮率は、runner起動・cache hit率を含む実workflowで再確認する。
- Linux Fullは個人開発のmain品質ゲートから除外した。Linux互換性の定期確認が必要になった場合は、手動workflowまたは別途nightly jobを検討する。
- Oracleのスキーマ・マスタ事前投入による高速化は今回の対象外。Oracle workflowでは既存の安全な初期化・cleanup方針を維持する。
