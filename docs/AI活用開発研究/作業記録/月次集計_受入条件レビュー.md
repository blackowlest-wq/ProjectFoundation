## 4. セキュリティ・性能判定

- 認証/認可: 計画段階で通過。401 path metadata、403先行、Repository 0回を実装後に確認する。
- CSRF: GETかつDB不変であり追加対策なし。CookieセッションとBackend認可は維持する。
- 入力: 形式完全一致、エラー非開示、bind parameterの計画で通過。
- ログ: query値・氏名・SQLを出さず、requestId/feature/useCase/statusを200/401/403で確認する条件で通過。
- 性能: 最大4本の固定集約SQL、DB側期間/状態絞り、既存索引利用、N+1なしの条件で通過。初回想定量では新規索引不要。
- DB不変: GET、read-only transaction、前後比較の条件で通過。

## 5. 保留とHard Gate

- F-012 CSVと想定量超過時の索引は対象外で、再確認条件を正本へ記録した。
- Oracle環境の有無はDoを止めないが、`F-011-AC-012`と機能完了は対象commitの`E2EOracle`成功まで保留する。
