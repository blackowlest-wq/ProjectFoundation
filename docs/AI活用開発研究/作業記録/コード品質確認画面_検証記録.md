## 表示上の保留・機械検証結果

- Backend JaCoCoは既存レポートを読み取り、全体Branch 79.71%が基準未達のため「未通過」として表示している。
- `AuthController`のBranch 1/2を未通過分岐として表示している。
- Backend・Oracleケースは既存レビュー記録に合わせて、資格情報エラーによる未実行として表示している。
- `BE-AUTH-010`、`BE-AUTH-012`、`FE-AUTH-011`の`reviewStatus`と`LOGIN-EXP-001`の`要補足`は入力レビュー記録として保持するが、機械検証結果には含めていない。
- Oracle接続環境の再確認は、既存のログイン機能レビュー記録に従う。

## GPTレビュー対応

| 指摘 | 対応結果 | 判定 |
| --- | --- | --- |
| 1. 設計品質・実行状態・総合判定の分離 | 受入条件の総合評価表示を廃止し、設計状態・実行状態・確認状況を個別表示 | 標準化候補 |
| 2. AC-006の品質ゲート化 | AC-006を通常の受入条件から除外し、QG-001へ移行 | 標準化候補 |
| 3. 双方向トレーサビリティ | 生成時に相互参照不一致をエラー検出 | 標準化候補 |
| 4. 根本原因集約 | rootCauses定義でブロッカーと影響ケース数を集約 | 標準化候補 |
| 5〜10. 総合判定・証跡・リンク・フィルター・検証・名称 | 総合評価を表示せず、実行情報表示、品質ゲート・証跡・画面内遷移、フィルター連動、検証強化、タイトル変更を実装 | 既存観点で対応 |

1〜4はコミット`1ee6e91`で先行確定後に検証し、5以降を追加実装した。

今回の追加方針「AIやモデルに依存する総合評価を表示せず、ゲート適用状況などの事実を表示する」は、他機能にも適用する標準化候補とする。
