## 目的と適用条件

Backendのmain/test JavaコードへPMDの次の3ルールを適用し、既存・新規の違反を品質ゲートで失敗させる。

| ルール | 閾値 |
| --- | --- |
| `CognitiveComplexity` | 15 |
| `CyclomaticComplexity`（method） | 10 |
| `CyclomaticComplexity`（class） | 80 |
| `NPathComplexity` | 200 |

抑制、baseline、既存違反の除外は設定していない。PMDは`Full`、`FullBackend`、Backendの`Simple`で実行する。

## 外部ドキュメント確認

実装前にPMD公式ドキュメントを確認した。

- Maven PMD Plugin: <https://pmd.github.io/pmd/pmd_userdocs_tools_maven.html>
- Java Design Rules: <https://pmd.github.io/pmd/pmd_rules_java_design.html>
- Ruleset authoring: <https://pmd.github.io/pmd/pmd_userdocs_making_rulesets.html>
- Rule configuration: <https://pmd.github.io/pmd/pmd_userdocs_configuring_rules.html>

PMD公式の既定値に合わせ、Cognitive 15、Cyclomatic method 10 / class 80、NPath 200を採用した。使用したMaven PMD Pluginは`3.23.0`で、実行時PMDは`7.0.0`だった。

## 変更内容

- `backend/pom.xml`へ`maven-pmd-plugin:3.23.0`を追加し、`backend/config/pmd.xml`をmain/test Javaへ適用した。
- `backend/config/pmd.xml`へ3ルールと閾値を定義した。
- `scripts/check.ps1`の`FullBackend`、Backendの`Simple`へ`pmd:check`を追加した。
- `scripts/pmd.tests.ps1`を追加し、POM、ruleset、閾値、各runnerへの登録を契約化した。
- `RequestContext`の経路判定を順序付き定義へ整理した。
- 保存済み日報の検証を`StoredReportRules`へ分離し、`TimeRules`の複雑度を下げた。
- 日報検索期間の検証を`DailyReportDateRangeValidator`へ共通化した。
- 品質ゲート運用資料、静的解析チェック表、開発フローへPMD導入済みの扱いを反映した。
