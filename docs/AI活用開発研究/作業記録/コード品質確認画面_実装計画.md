# F-001 ログイン機能 コード品質確認画面 Implementation Plan

> **Codexでの実行:** 実装前に`/plan`でこの既存計画と現在のリポジトリ状態を照合する。長時間・多段階の実行では、合意した結果、制約、検証を含む`/goal`を開始する。チェックボックスは進捗記録に使い、未確認の項目を現行要件として扱わない。

**Goal:** F-001ログイン機能の受入条件、テストケース、実テスト、証跡、観点判定、カバレッジ状態を、機能別の自己完結型HTMLで確認できるようにする。

**Architecture:** `F-001_ログイン_表示データ.json`を表示用スナップショットとし、`F-001_ログイン_生成.ps1`が入力検証後にJSONをHTMLへ埋め込む。生成後の`F-001_ログイン_コード品質確認.html`は外部リソースなしで動作し、既存資料・テスト・ソース・カバレッジへ相対リンクする。

**Tech Stack:** PowerShell、JSON、HTML、CSS、Vanilla JavaScript。外部npmパッケージ、CDN、アプリ本体コードへの変更は行わない。

## Global Constraints

- 対象機能は`F-001 ログイン`全体とし、`S-001`、ログインAPI、ログアウト、`/me`、セッション、CSRF、Oracle確認を表示対象に含める。
- 成果物は`docs/AI活用開発研究/コード品質確認画面/F-001_ログイン/`へ配置する。
- 受入条件、テストケース、実テスト、指摘の既存ID名前空間を変更しない。
- HTMLは`file://`で開ける自己完結型とし、外部サーバー、CDN、認証情報を必要としない。
- カバレッジ未生成は未通過分岐と扱わず、`未生成`または`未確認`として表示する。
- 簡易修正モードを適用し、アプリ本体のFull、E2E、Oracle、カバレッジ再生成は必須検証にしない。
- パスワード、トークン、Cookie値、Oracle接続情報、秘密値を表示用JSONとHTMLへ含めない。

### Task 2: JSON検証とHTML生成スクリプトを作成する

**Files:**

- Create: `docs/AI活用開発研究/コード品質確認画面/F-001_ログイン/F-001_ログイン_生成.ps1`

**Interfaces:**

- Consumes: `F-001_ログイン_表示データ.json`、任意の`-DataPath`、任意の`-OutputPath`。
- Produces: 自己完結型`F-001_ログイン_コード品質確認.html`、または`-ValidateOnly`時の検証結果。

- [ ] **Step 1: パラメーターと既定パスを定義する**

  次のパラメーターを定義する。

  ```powershell
  param(
      [string]$DataPath = (Join-Path $PSScriptRoot 'F-001_ログイン_表示データ.json'),
      [string]$OutputPath = (Join-Path $PSScriptRoot 'F-001_ログイン_コード品質確認.html'),
      [switch]$ValidateOnly
  )
  ```

  `-ValidateOnly`はHTMLを書き出さず、入力検証だけを実行する。

- [ ] **Step 2: JSONの必須項目と許容値を検証する**

  `feature`、`acceptanceCriteria`、`testCases`、`viewpoints`、`testImplementations`、`evidence`、`findings`、`coverage`、`sources`の存在を確認する。IDの重複、受入条件・ケース・実テスト・証跡・ソースの参照先不在、レビュー判定以外のステータス、カバレッジ判定以外のステータスをエラーにする。

- [ ] **Step 3: HTMLへ安全にデータを埋め込む**

  `ConvertTo-Json -Depth 20 -Compress`でJSONを生成し、`</script>`として解釈されないように閉じタグ文字列をエスケープして、HTML内の`<script type="application/json" id="quality-data">`へ埋め込む。表示用データにパスワード値、トークン形式、接続文字列が含まれていないことを生成前に検査する。

- [ ] **Step 4: 自己完結型HTMLの基本レイアウトを生成する**

  HTMLには、タイトル、対象機能、生成日時、対象コミット、概要カード、タブまたは見出し、CSS、Vanilla JavaScriptを埋め込む。外部CSS、画像、フォント、CDN、fetchによるJSON読込は使用しない。

- [ ] **Step 5: 生成コマンドを検証する**

  Run: `pwsh -NoProfile -ExecutionPolicy Bypass -File './docs/AI活用開発研究/コード品質確認画面/F-001_ログイン/F-001_ログイン_生成.ps1' -ValidateOnly`

  Expected: JSON検証が成功し、HTMLファイルが変更されない。
