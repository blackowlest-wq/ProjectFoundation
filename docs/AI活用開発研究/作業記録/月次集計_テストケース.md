# 月次集計 テストケース

## 1. 文書の位置づけ

- 対象機能: `F-011 月次集計`
- 対象API: `A-016 GET /api/monthly-summaries`
- 対象画面: `S-008 月次集計画面`
- 本資料をF-011の正本テストケースとする。
- 受入条件ID、テストケースID、実テストID、指摘IDは別名前空間で管理する。

## 2. 承認対象の設計判断

以下はF-011、A-016、既存DB契約を実装可能な期待値へ具体化した判断である。Do開始の承認をもって確定する。

1. 社員別作業時間は承認済み`daily_reports.work_minutes`（実勤務時間）を社員ごとに合計する。案件別・分類別は承認済み日報に属する`daily_report_work_items.work_minutes`を合計する。
2. 休日区分別日数は暦日の重複排除ではなく、承認済み日報の社員日数、すなわち休日区分ごとの日報件数とする。同日に2社員なら2日と数える。
3. 作業なしの承認済み休日は社員別集計に残し、`COALESCE(SUM(work_minutes), 0)`により0分とする。案件別・分類別には行を作らない。
4. 対象0件のAPIは`yearMonth`と4個の空配列を返す。画面概要は対象社員`0名`、総作業時間`0分`を表示し、各表は空状態を表示する。
5. 正常時の画面概要は社員配列の件数と社員別作業時間の合計だけを表示する。S-008モックの有給日数・休日作業カードはA-016から一意に導出できないため対象外とする。
6. 初期年月はブラウザのローカル年月とする。4切替は自動選択型のWAI-ARIA tabsとし、左右矢印でフォーカスと選択を移動する。
7. API配列の順序は契約化せず、テストはIDまたは休日区分をキーに順序非依存で完全一致を確認する。

## 3. 対象範囲・対象外

- 管理者による対象年月指定、`APPROVED`限定、4集計、0件、境界、認証・認可、入力、ログ、API/UI/Mock E2E/Oracle E2Eを対象とする。
- F-012 CSV、集計テーブル・バッチ、ページング、マスタ保守は対象外とする。
- 新規索引は初回想定量（社員20名、12か月）では追加しない。想定量または実測が変わった場合に再検討する。
