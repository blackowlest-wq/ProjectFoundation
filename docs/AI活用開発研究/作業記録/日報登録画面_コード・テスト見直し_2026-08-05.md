# 日報登録画面 コード・テスト見直し記録（2026-08-05）

## 目的

日報登録画面を対象に、用語台帳で確定した正式名称をコード・テストへ反映し、同時実行時の状態競合を`V-TRN-010`に沿って検出できるようにする。

## 実装前確認

- 対象機能: F-002 日報登録、F-003 日報編集、F-006 日報提出、F-009 日報再提出、承認・差戻しの状態変更。
- 用語: 画面表示は「社員名」「勤務開始時刻」「勤務終了時刻」、`DRAFT`の正式な日本語は「下書き」。認証・認可の境界で使う「利用者」は意味が異なるため残す。
- API互換性: JSONの`workMinutes`は変更せず、内部の実勤務時間を`actualWorkMinutes`、日報明細の時間を`workItemMinutes`へ整理する。
- 同時更新方式: `DailyReportEntity`の行を変更系トランザクションの開始時に`PESSIMISTIC_WRITE`でロックする。スキーマ変更なしで、先行処理のコミット後に後続処理が最新状態を再評価できる。
- 変更対象: 社員本人の日報更新・提出・再提出、上長の承認・差戻し。詳細・一覧の参照処理はロック対象にしない。
- テスト方式: フロントエンドは既存Unitへ用語期待値を追加し、BackendはOracle実DB上でRepositoryロックの待機・解放を確認する。既存の順次状態エラー確認と組み合わせて、競合時の再評価を検証する。
- 公式確認: [Spring Data JPA locking](https://docs.spring.io/spring-data/jpa/reference/jpa/locking.html)、[Jakarta Persistence LockModeType](https://jakarta.ee/specifications/persistence/4.0/apidocs/jakarta.persistence/jakarta/persistence/lockmodetype)を確認した。新規ライブラリ・外部APIは追加しない。

## 変更結果

### 用語・命名

- `DailyReportForm`の画面ラベルを「社員名」「勤務開始時刻」「勤務終了時刻」へ変更した。
- `DRAFT`の日本語表示を「下書き」に統一し、Frontend既定値、Backend既定値、Oracle seed、対象設計書、現行テストケースを更新した。「未提出」は旧称として用語台帳にだけ残した。
- 認証・認可境界の「利用者」は、ログインアカウントを表すため変更していない。
- API JSONの`workMinutes`は変更せず、Entity・計算record・内部変数・テストヘルパーを`actualWorkMinutes`／`workItemMinutes`へ整理した。Frontend型にはAPI互換項目であることを注記した。

### 状態競合

- `DailyReportRepository.findByReportIdAndEmployeeUserId`と`findByReportIdForUpdate`へ`PESSIMISTIC_WRITE`を指定した。
- 日報本人の更新・提出・再提出、上長の承認・差戻しでロックを取得し、先行トランザクションのコミット後に状態判定する。
- `DailyReportConcurrencyTest`で、先行処理が`PENDING`へ変更してロックを保持している間に後続提出APIを実行し、待機後に`409 INVALID_STATUS`となることを確認した。

## 保留・運用上の注意

- 既存環境の`message_catalog`に旧値が登録済みの場合は、デプロイ時に`seed-master-data.sql`相当の更新を適用する必要がある。初期化・再適用用seedは「下書き」へ更新済み。
- `未提出`は旧称として用語台帳に残している。新規資料・コード・テストでは「下書き」を使用する。
- `利用者`は認証・認可の用語として残している。日報登録画面の社員表示には「社員名」を使用する。
