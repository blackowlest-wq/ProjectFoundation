## 目的

作業開始時に利用者が`簡易修正モード`または`品質重視モード`を選択できるようにし、Simpleではローカル確認をFocused Unit、必要時のbrowser 1ケース、変更対象層のlint / typecheck / build、独立コード差分レビュー1回へ整理する。全体回帰は既存CIへ委譲するが、既存hookとPR必須CI 6チェックは維持する。

Simpleは変更カテゴリや規模を理由に自動昇格しない。API契約、DB、DDL、SQL、業務ルール、状態遷移、入力検証、CI、workflow、品質ゲートも対象外とせず、対象レイヤーのFocused Unit、静的チェック、レビュー、CIへ対応付ける。

## 外部ドキュメント確認

PowerShellの`ValidateSet`を含む高度な関数パラメータ、npm exec、Playwright CLIのgrep実行、Maven Surefireの`-Dtest`指定を実装前に公式資料で確認した。

- PowerShell: <https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_functions_advanced_parameters?view=powershell-7.6>
- npm exec: <https://docs.npmjs.com/cli/v11/commands/npm-exec/>
- Playwright Test CLI: <https://playwright.dev/docs/test-cli>
- Maven Surefire test: <https://maven.apache.org/surefire/maven-surefire-plugin/test-mojo>

確認結果は、CLI引数を固定の配列で渡し、Focused UnitやPlaywrightの対象を入力検証する実装へ反映した。任意のシェル文字列、`Invoke-Expression`、`cmd /c`は使用していない。

## モード別の記録契約

Simpleを選択した個別変更では、PR本文または1枚の変更記録へ次を残す。

1. 受入条件3～5項目
2. Focused Unit対象またはN/A理由
3. 表示要件の有無、必要時の既存browser 1ケースまたは手動確認理由
4. 変更対象層のlint / typecheck / build結果
5. 独立コード差分レビュー1回の結果
6. 全体回帰をCIへ委譲したこと、未実行理由、再確認条件

品質重視モードでは、既存の専用仕様書、実装計画、AC/TC/RT台帳、観点別レビュー、実装後レビュー、統合品質記録を適用する。今回のハーネス基盤変更は品質重視で扱うため、本設計・本計画・本作業記録を作成した。

- P1 静的解析・CI・品質ゲート: Simpleは`CiTask`、Full、Oracle、coverage、E2E、追加Gitleaks定義を呼ばず、既存hookとPR必須CIの定義を変更していない。

### 未実行と再確認条件

- Oracle実接続、Backend coverage、Oracle E2Eは、保護されたOracle環境と専用runnerが必要なためローカルでは実行しない。main反映後に既存Oracle workflowの環境条件が揃った場合に再確認する。
